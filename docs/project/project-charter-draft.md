# ChangeScope 项目章程（待团队审核）

## 1. 项目名称与目标

**项目名称：** 基于 Git 历史挖掘的代码变更风险分析与审查决策支持系统（ChangeScope）。

**目标：** 为中小型 GitHub 协作开发团队提供文件历史共变更分析、可解释的 PR 风险提示、审查员推荐和质量反馈；辅助人工审查决策，不代替 GitHub 的创建、评论、批准与合并流程。

**受益对象：** 开发人员、代码审查员、质量管理员；同时关注系统维护者与仓库所有者的权限及成本诉求。

## 2. 当前范围（草案）

- 核心 A：仓库历史提交获取、文件共变更频次与条件关联强度
- 核心 B：PR 变更规模、历史活跃度、关联文件风险的可解释评分
- 核心 C：基于相关文件经验、近期负载与自审约束的审查员推荐
- 核心 D：风险提示反馈、规则版本与效果评价

**不做：** 自建 GitHub PR 审批、评论、通知系统；自动合并代码；训练大型模型。

## 3. 项目角色与权限

系统业务角色不少于3种：开发人员、代码审查员、质量管理员；采用项目范围内的权限控制。初始外部集成方案为 GitHub OAuth + GitHub REST API。

## 4. 建议过程模型

采用**增量开发 + 迭代评审**：v0.1 Git 历史/共变更、v0.2 PR 风险、v0.3 审查决策与反馈。保留至少2轮“计划-构造-测试-评审”迭代；需求阶段使用用户故事 Issue + PR 评审建立可追溯基线。

选型理由：核心模块可以递进交付；GitHub API 限制与分析算法效果存在技术不确定性，需要原型和反馈逐步降低风险。

## 5. 课程规模核对（方案，非完成情况）

- 系统角色：3种；项目级权限控制
- 用例：课程设计文档列有22个功能用例 + 2个非功能场景
- **本轮课堂用户故事：** 候选20条功能 + 3条非功能，必须通过真人调研确认并逐条 Issue 化
- 分析类：项目设计文档规划18个，后续通过 CRC/类图完善
- 可交付增量：3个；外部集成：至少1处；技术风险：至少1项

## 6. 里程碑（相对课程检查点）

1. 第2课后：需求访谈证据、调研报告、用户故事 Issue。
2. 第3课：SRS v1.0、用例/场景、非功能指标、需求追踪矩阵（以教师课堂要求为准）。
3. 后续：分析建模、设计建模、至少两轮迭代、测试部署。
