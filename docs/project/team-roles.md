## 协作规则

1. 不直接 push 到 `main`，每个变更从 Issue 出发，提交 PR 后由另一人 Review。
2. 每次 PR 写明对应 Issue 编号、测试或文档核对方式及人工审核人。
3. 调研、需求取舍与签字确认由真人完成；AI 可辅助归类与改写，不得编造用户反馈。
4. 四人都要参与需求评审和代码评审，后续至少两轮完整迭代保留计划与回顾。
5. 第一次需求报告由 A、C 编写，B、D 交叉核对证据；算法原型由 B 编写，D 运行测试。
6. 教师要求的系统角色是：开发人员、代码审查员、质量管理员；它们不是本表的四个团队成员。
