# 用户故事 Issue 草稿（尚未确认）

本目录提供 **20条功能故事 + 3条非功能故事**，方便访谈后录入 GitHub。

**这些不是已经建好的 GitHub Issues，也没有真实调研证据。**

操作顺序：

1. 真人访谈并合规归档证据。
2. 四人评审各条是否有独立用户目标；可合并、替换、删除不真实的故事，最终保持不少于20条、其中至少3条非功能。
3. 对确认的故事修改内容、明确可测试的验收标准，把 `TODO` 证据改成具体的访谈/报告链接。
4. 在 GitHub **每条独立创建一个 Issue**，标签 `story`，指定真实 GitHub Assignee；本地编号对应 Issue 编号。
5. 将 Issue URL 回填 `../user-stories-index.md`。
6. 把故事标记为“已确认”仅当团队完成需求评审后，不能因为 AI 起草而自动确认。
