# CR-CAND-01｜PR合并状态提示（候选扩展，未评审）

> **状态：待用户确认 / 待技术评估 / 未纳入本期必做范围。**
> 背景：项目组成员回忆此前同学交流时提到**合并冲突**与**PR审查繁琐**两类困难；尚无当场记录、人数统计或受访者核对证据。

## 候选用户故事

作为在GitHub上协作的开发人员，我想在查看 PR 分析结果时同时看到其**GitHub已报告的合并状态**，以便在进入正式合并流程之前知道是否需要回GitHub检查合并冲突。

**注意：** 这是从回忆线索推导的解决方案，**不是受访者明确要求的功能**；须先向实际开发人员求证。

## 功能边界

- **拟支持：** 若授权范围允许、且 GitHub 返回了可靠的 PR 状态，可显示“可合并 / 存在冲突 / 正在计算或未知”，并提供到 GitHub 原生 PR 页面解决问题的入口。
- **不支持：** 自动作出“冲突代码正确修复”的判断、自动合并、自动改写文件、替代GitHub处理冲突。
- **不混淆：** Git 合并冲突属于分支内容冲突；Git 历史共变更概率不等于 Git 可合并状态，也不能作为冲突检测结果。
- **待确认：** GitHub接口是否按实际权限稳定提供可合并状态、同步时效、异常及限流的处理策略。

## 候选验收标准（尚未经评审）

- **Given：** 用户已登录并获得某 PR 的访问授权，GitHub 对该 PR 明确报告不可直接合并；
- **When：** 用户打开该 PR 的 ChangeScope 辅助分析页面；
- **Then：** 系统展示“存在合并冲突”并提供指向 GitHub 原PR的跳转入口，不提供自动修复按钮。

补充分支：
- **Given：** GitHub 尚未计算完成或 API 出现错误；
- **When：** 用户查看合并状态；
- **Then：** 系统显示“未知 / 待更新”，而不是“无冲突”或“可合并”。
